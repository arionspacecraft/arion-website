# Q&A 연결과 운영

2026-10-19: ARION 조직의 서울 리전 프로젝트 `arion-qna` (`wchxbwowikorhtdgnlbg`)에 초기 DB를 적용했습니다. 익명 로그인과 운영진 계정 등록, 실제 익명 제출·비공개·권한 거절·중복 방지·등록 제한, 실제 운영진 로그인·답변 게시·숨기기를 확인했습니다. `main` 병합 시 기존 GitHub Actions가 공식 사이트에 배포하며, 최신 배포 결과는 Actions와 기존 Obsidian 운영 노트에서 확인합니다.

## 구성

- 홈페이지는 기존 GitHub Pages 주소를 유지합니다. Supabase Auth와 PostgreSQL이 질문·답변을 보관합니다.
- 읽기는 로그인 없이 가능하고, 질문 제출 시 익명 Auth 세션을 생성합니다. 이메일·비밀번호는 질문자에게 요구하지 않습니다.
- 접수된 질문은 처음에는 비공개이며, 운영진이 공개할 질문 문구를 검토하고 답변을 저장해야 질문과 답변이 함께 공개됩니다. 답변·수정·숨기기와 비공개 질문 열람은 등록된 운영진만 가능합니다. 화면을 우회해 API를 직접 호출해도 데이터베이스 함수가 권한을 검사합니다.
- 기존 브라우저 미리보기 글은 자동 공개하거나 서버로 업로드하지 않습니다. 미연결 개발 서버의 기존 미리보기와 운영의 준비 중 안내는 유지됩니다.
- 공개 목록에는 답변이 있는 질문의 ID·검토된 제목/본문·작성일·답변·답변일만 포함합니다. 이름·전화번호·이메일은 선택 입력이며 운영진만 열람합니다. 공개 작성자는 익명으로 표시합니다. 미답변 질문은 공개 검색 결과와 건수에도 포함되지 않습니다. 로그인 이메일, 사용자 ID 및 운영진 등록 목록은 공개하지 않습니다.
- 글은 HTML을 실행하지 않는 일반 텍스트로 표시합니다. 제목 100자, 질문 2,000자, 답변 4,000자 제한입니다. 페이지당 20개이며 새로고침으로 최신 답변을 확인합니다.
- 공개 RPC는 `SECURITY INVOKER`이며, 필요한 권한을 가진 구현 함수는 노출하지 않는 `qna_private` 스키마에 둡니다. 원본 테이블 권한은 모두 회수하고 RLS도 켰습니다. 운영진도 테이블을 직접 읽지 못하며, 매 요청 운영진 목록을 확인하는 함수로만 접근합니다.

## 연결 이력

- 사용자 지정 조직 ARION, 서울 리전 `ap-northeast-2`, Free 요금제에 프로젝트를 생성했습니다.
- 운영진은 사용자가 직접 만든 `arionspacecraft@gmail.com` 비익명·이메일 확인 완료 계정 1명입니다. 비밀번호는 코드·로그·문서에 저장하지 않습니다.
- 로컬과 GitHub Actions Repository variables에 프로젝트 URL과 현대식 publishable key를 등록했습니다. 서버 secret/service role 키는 사용하지 않았습니다.
- Supabase 보안/성능 검사에서 WARN/ERROR는 없었습니다. 비공개 테이블 3개의 RLS 정책 없음은 직접 접근을 거부하는 의도된 설정입니다([안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)). 생성 직후 미사용 인덱스 INFO 4개는 유지했습니다([안내](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index)).
- 실제 SDK 세션과 브라우저에서 각각 테스트 질문을 등록했습니다. 답변 전 공개 건수·검색은 0, 재시도는 동일 ID, 비운영진의 관리자 목록/답변/숨기기는 거절됨을 확인했습니다. 별도 비로그인 세션에서 운영진이 검토한 제목·본문·답변만 반환되고 테스트 연락처·원문은 포함되지 않았습니다. 검증 글 2개는 운영진 화면에서 숨겼으며 삭제하지 않았습니다.
- 브라우저에서는 사용자 본인이 비밀번호로 로그인한 뒤 비공개 연락처 조회→공개 문구 검토→답변 게시→숨기기를 확인했습니다. 관리자·질문 폼의 모바일 390px, 한영 문구·라이트/다크도 점검했습니다. 최초 원격 검증 [Actions 39210984942](https://github.com/arionspacecraft/arion-website/actions/runs/39210984942)은 전체 175개 테스트, 실제 Notion 4개 프로젝트 동기화 및 20개 직접 진입 경로 빌드를 통과했습니다.

## 연결 절차

1. 사용자가 소유한 Supabase 프로젝트를 선택합니다. 새 유료 프로젝트나 요금제는 임의로 만들지 않습니다. 운영진 계정을 지정할 이메일을 사용자에게 확인합니다.
2. 새 프로젝트에는 `supabase/migrations/202610190001_qna.sql`을 한 번 적용합니다. 현재 운영 프로젝트에는 적용 완료했으므로 재실행하지 않습니다. 이후 변경은 별도 증분 마이그레이션으로 작성합니다. `qna_private`는 API의 exposed schemas에 추가하지 않습니다. 초기 SQL은 새 전용 테이블만 만들며 기존 테이블을 수정하거나 삭제하지 않습니다.
3. Auth의 Anonymous Sign-ins를 활성화합니다. 사이트에서 운영진 회원가입은 제공하지 않습니다. 운영진은 Auth에서 비익명 계정으로 생성하고 비밀번호는 본인이 설정합니다. 인증 비밀값을 채팅·Git·노트에 기록하지 않습니다.
4. 확인된 운영진 계정을 데이터베이스 소유자로 등록합니다. 아래 예시 이메일을 **실제 확인한 값으로** 바꿉니다. 일치하는 계정이 1개인지 먼저 확인하고, 익명 계정은 등록하지 않습니다.

```sql
select id, email, is_anonymous from auth.users where email = 'confirmed-staff@example.org';
insert into qna_private.staff (user_id)
select id from auth.users
where email = 'confirmed-staff@example.org' and is_anonymous = false
on conflict do nothing;
```

5. 로컬 `.env.local`과 GitHub Actions Repository variables에 다음 공개 설정 두 개를 넣습니다. 운영 빌드에 포함되는 값이므로 **publishable key만** 허용합니다. `service_role`, secret key, DB 비밀번호는 사용하지 않습니다. Vite 검사가 `sb_publishable_` 이외 키를 거부합니다.

```dotenv
VITE_SUPABASE_URL=https://PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

6. 실제 연결 상태에서 아래 검증을 완료하고 검토된 커밋을 main에 병합합니다. 기존 GitHub Actions가 같은 공식 사이트에 배포합니다. 원격 쓰기 계정은 `arionspacecraft`인지 확인합니다.

## 검증

- `npm test -- --maxWorkers=2`, `npm run lint`, `npm run build`, `git diff --check`.
- `tests/qnaDatabase.test.ts`는 실제 마이그레이션을 로컬 PostgreSQL(PGlite)에 적용하고 역할별 권한·재시도 중복·등록 제한·검색·페이지 구분·숨기기를 검사합니다. Auth/JWT는 테스트에서 구성한 입력이므로 실제 Supabase 인증·네트워크 검증을 대신하지 않습니다.
- `tests/LiveQnaBoard.test.tsx`는 API 대역으로 실패 초안 보존, 요청 중복 방지, 오래된 검색 응답 무시, 운영진 UI, 영어 문구 등을 검사합니다.
- 실제 연결 후 서로 다른 브라우저 세션에서 질문 등록→공개 목록/검색/건수에서 비노출 확인→운영진 비공개 목록에서 연락처 확인→답변과 정리한 질문 공개→비로그인 재조회 및 연락처 비노출 확인 순서로 확인합니다. 비운영진 토큰으로 답변·숨기기 요청이 거절되는지도 확인합니다. 로그인 실패/만료, 재시도, 한국어·영어와 모바일·양 테마도 검사합니다.
- 운영용 테스트 글은 테스트임을 명시하고 검증 후 운영진 숨기기로 비공개 처리합니다. 사용자가 작성한 글을 삭제하지 않습니다. 공개 배포를 완료했다고 기록하기 전에 Actions 성공과 실제 운영 URL의 등록·답변을 확인합니다.

## 운영과 제한

- `/qna/admin`에서 등록 계정으로 로그인합니다. 답변 대기/공개 중/숨김 목록을 선택하고 질문을 펼쳐 원문·연락처를 확인합니다. 공개할 제목·본문에서 개인정보를 제거하고 답변을 작성한 뒤 확인란을 체크해 ‘답변 저장 및 공개’를 누릅니다. 공개 내용과 원문은 별도로 보관합니다. 답변 수정·질문 숨기기도 가능합니다.
- 숨기기는 질문·답변을 삭제하지 않습니다. 복구가 필요하면 관리자 SQL에서 지정한 질문의 `hidden_at`, `hidden_by`를 NULL로 되돌립니다. 비공개 글 내용을 일반 방문자에게 반환하지 않습니다.
- 익명 사용자별 1분 1건·최근 24시간 10건 제한을 서버에서 검사합니다. 같은 사용자·요청 ID 재시도는 기존 질문 ID를 반환합니다. 네트워크 실패 후 초안 그대로 재시도하면 중복 글이 생기지 않습니다.
- 브라우저 데이터를 지우면 새 익명 사용자로 인식될 수 있으므로 위 제한은 사람/IP당 완전한 스팸 방지가 아닙니다. Supabase Auth의 IP 제한을 유지하고 실제 사용량을 관찰합니다. CAPTCHA를 켜려면 사이트의 CAPTCHA 위젯과 `captchaToken` 전송도 함께 추가해야 하며, 백엔드 설정만 켜면 현재 등록이 실패합니다.
- 질문 작성자 자신의 수정·삭제, 답변 알림, 첨부파일, 자동 실시간 갱신은 현재 범위에 포함되지 않습니다. 공개 질문에 개인정보를 쓰지 않도록 안내합니다.
- 이 마이그레이션은 사용자 참조를 보존하므로 작성 기록이 있는 Auth 사용자를 임의 삭제하지 않습니다. 보존 정책은 실제 운영 필요를 확인한 뒤 별도 결정합니다.

참고: [Supabase 익명 인증](https://supabase.com/docs/guides/auth/auth-anonymous), [데이터베이스 권한](https://supabase.com/docs/guides/database/postgres/row-level-security), [비밀번호 로그인](https://supabase.com/docs/reference/javascript/auth-signinwithpassword).

## 관리자 바로가기와 코드 공개

- 질문 작성란에서 사이트에 공개된 정우진의 이름·전화번호와 이메일 칸의 `arion2026`이 일치하면 관리자 로그인 화면으로 이동합니다. 제목·본문을 입력할 필요는 없고 질문 등록 API도 호출하지 않습니다.
- 이 조합은 **공개 가능한 이동용 문자열**입니다. 비밀번호·권한·인증 수단이 아닙니다. 관리자 URL에 직접 접속해도 동일하게 실제 운영진 계정 로그인이 필요합니다. 관리자 목록 RPC는 매 요청 서버의 운영진 등록을 검사합니다.
- GitHub 저장소를 비공개로 하더라도 브라우저에 전송된 HTML/JS/CSS와 이 이동 조건은 열람 가능합니다. 저장소 가시성은 변경하지 않았습니다. 운영진 비밀번호나 서버 secret key를 프런트엔드 코드에 넣지 않습니다.
- 로그아웃/인증 상실 시 비공개 목록 컴포넌트를 제거하고, 보호된 목록 요청이 실패하면 화면의 연락처 캐시를 비웁니다. 연락처와 질문 초안은 localStorage에 저장하지 않습니다.
- 선택 연락처의 실제 보존 기간/운영 정책은 서비스 연결 전에 사용자와 확정합니다. 코드나 화면에 임의의 보존 기간을 약속하지 않습니다.
